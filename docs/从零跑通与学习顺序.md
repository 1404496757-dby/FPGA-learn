# 两个项目的实际学习入口

先把学习目标定为：能够预测一个信号下一拍的值，能解释一个异常为什么发生，能自己改动并验证。跑完脚本只是第一步。

## 第一步：FIFO，而不是先读整套JPEG-LS

打开 `rtl/common/stream_fifo.v` 与 `sim/tb_common.sv`，运行 `scripts/run_sim.ps1 -Test common`。

画三个状态：RAM中有几个字、输出寄存器是否有效、消费者是否接受。手推四拍：写入一个字、RAM预取、消费者暂停、消费者接收。回答为什么预取会移动rptr，但不能表示数据已经发到下游。

再解释 `level=ram_count+m_valid` 和 `s_ready=reset_done&&(!full||pop)`。在输出暂停时记录m_data与m_valid，确认它们保持。把DEPTH缩为8，观察满时同拍读写为什么还能接受一个新字。

异步FIFO和事件CDC先作为单独练习：前者用RAM保持数据、用Gray指针跨域；后者通过req/ack保存事件。两个板级主工程各自只有一个处理时钟域，不需要人为插入跨域。

## 第二步：通信项目由模块到串行引脚

按这个顺序阅读：`comm_service.v` → `spi_byte_engine.v` → `comm_acx750_top.v` → `vendor/uart/uart_rx.v`、`uart_tx.v`。

分别运行 `-Test comm`、`-Test spi`、`-Test uart_board`。前者是字节接口级测试，后者才让数据经过串行UART收发。测试中的SPI四模式回环用于核的行为检查，不等同于已经接过外部传感器。

请求 `A5 00 01 13 B7` 如何经过FIFO与状态机形成 `5A 00 01 13 48`？逐字节追踪state、qvalid/qready和reply_index。暂停tx_ready，解释结果如何保存。试着自己增加“读取完整32位丢字节计数”的命令，并同时修改协议与测试期望。

顶层中的SPI是内部MOSI/MISO回环。上板先用echo确认UART与引脚，再用spi确认封装链路；接外部SPI器件需要新增真实GPIO约束、CS连接及器件协议。

## 第三步：先理解图像服务，再进入编码算法

读 `rtl/image/jls_frame_service.v` 与 `sim/tb_image.sv`，运行 `-Test image`。

先画状态转移图：同步头 → 序号 → 像素 → CRC → 初始化 → 读像素/送像素 → 排空 → 回包。弄清楚4096字节图像存在哪里，为什么BRAM读需要等待，为什么FEED_PIXEL每两拍才出现一次。

编码核不接受ready。对每个o_e有效字必须缓存；缓存满时继续接收并排空核心，最后回错误状态，不能把截断文件伪装成成功。测试平台同时实例化正常缓存和极小缓存来验证这一点。

查看本次仿真目录的 `image_0..3.jls`、原始/解码raw和pixel_check.json。用自己的话区分：CRC证明包内容完整，独立解码像素比较证明此次编码无损。比较常量与噪声图码长，解释为什么噪声图可能比原图更大。

随后读 `vendor/jls/jls_encoder.v`。从func_predictor和linebuffer开始，列出邻域像素与延迟，再读上下文、残差、Golomb-Rice与游程编码。开源算法核心应写作“集成与复现”；自己确实改动了算法后，再记录具体修改。

## 第四步：上板收集真正的证据

两个.bit分别加载，不能同时把两个独立顶层当成一个工程。板卡和引脚按ACX750资料，USB-UART COM口必须用实际值。

先运行通信客户端，再运行图像客户端。后者保存原图、完整回包、码流和解码像素；将日期、COM口、bitstream哈希、输入图案和终端输出一起存档。客户端缺少pyserial时，按README安装到自己使用的Python环境。

需要观察内部信号时再加ILA：建议先选state、FIFO level、valid/ready、丢字节计数。插入ILA后重新实现并检查时序，不能沿用未插入ILA的报告。

## 面试前的最低自检

- 不看代码，画出两个系统的数据路径与各块容量。
- 说明UART位宽、波特率、SPI频率与系统时钟之间的关系。
- 说明输出暂停、CRC错误、输入半包和缓存溢出各走哪条状态路径。
- 指出自己写的模块、引用的核和自己修改的地方。
- 给出一条实际失败记录和修复后的仿真/上板证据。
- 用具体输入计算一次PID乘积、34位累加、算术右移和饱和结果；解释PWM与STEP/DIR的区别。

这些都能独立完成后，项目才逐渐成为你能在面试中解释和修改的能力。
